# 电脑传歌工具与接口

首版采用同一 Wi-Fi 下的浏览器工具，同时保留 USB 文件共享。它与 iOS
本地导入使用同一个应用内曲库；以后独立电脑客户端可以复用相同接口。

## 使用流程

1. 电脑和手机连接同一局域网。
2. 手机从 Music 或 Settings 打开 Computer Transfer（中文“电脑传歌”），手动开启接收；默认界面语言为英文。
3. 点击 Copy Address（复制地址），在电脑浏览器打开完整地址，包括 `#` 后的临时配对令牌。
4. 拖入多个音频，或点击选择文件；页面逐项显示传输进度与导入结果。
5. 成功导入的歌曲出现在手机曲库中；结束后关闭接收。

可以短暂切换应用，把复制的地址发给电脑。应用使用 iOS 允许的有限后台运行
时间；额度用完后暂停接收并取消未完成的上传，回到应用后沿用同一个地址和
配对令牌恢复。大文件传输时保持应用在前台。手动关闭接收或退出应用会撤销
当前会话，下次开启生成新的令牌。每次会话只提供上传和曲库浏览，不提供删除、任意
文件读取、账号登录或云同步。

USB 补充方式：Mac 使用 Finder，Windows 使用 Apple Devices 的应用文件共享，
将音频拖入本应用的共享文件区，完成传输后刷新曲库或重新打开应用。应用会把
共享目录根部的有效音频整理到 `Music`，重名保留，无法解析的源文件留在原处。
[Apple 操作说明](https://support.apple.com/en-ie/119585)

## 通过 USB 打开传歌网页

如果电脑无法连接手机显示的 Wi-Fi 地址，Mac 可以用 USB 转发同一个传歌网页。
工具仅使用 Python 3 标准库和系统的 `usbmuxd`，无需安装第三方 Python 包。
它不会安装或启动手机应用，仍需在手机上手动开启 Computer Transfer。

1. 用 USB 连接 iPhone，解锁手机，并按系统提示信任电脑。
2. 手机保持 Computer Transfer 开启，复制当前完整地址，包括 `#` 后的令牌。
3. 在项目目录运行：

   ```sh
   python3 scripts/iphone_transfer_usb.py --open
   ```

4. 按提示粘贴手机地址并回车；输入会隐藏。浏览器打开终端显示的
   `http://127.0.0.1:某端口/`，随后自动配对。拖入音频即可使用同一上传界面。
5. 大文件上传期间让手机上的播放器保持前台；完成后在手机关闭接收，并在
   终端按 `Ctrl-C` 结束转发。

默认要求电脑只连接一台 USB 设备；多台设备时用 `--udid 设备标识` 固定选择。
可以加 `--listen-port 8765` 指定本地端口；默认由系统分配空闲端口。
脚本只监听电脑的 `127.0.0.1`，不会向局域网开放。每次新连接均核对同一 USB
设备，拔线后不会自动改连其他手机。终端不打印配对令牌，也不读取剪贴板。
自动化输入可用 `--url-stdin` 从标准输入传入地址；避免把含令牌的完整地址写进
命令历史或公共日志。

USB 转发只改变连接路径：512 MiB 单文件上限、后台额度到期暂停、手动停止撤销
令牌等规则与 Wi-Fi 方式相同。返回手机前台后可刷新本地页面重试；如果手动停止
后重新开启了接收，需要重新运行脚本并输入新地址。连接成功仅代表 USB 隧道
建立，手机应用暂停或未响应仍可能导致网页超时，不能据此确定 Wi-Fi 故障原因。

协议实现参考 [libusbmuxd / iproxy](https://github.com/libimobiledevice/libusbmuxd)。
离线测试覆盖分段协议读取、长度和 tag 校验、固定 USB 设备、二进制上传、
双向半关闭、超时与退出清理；真实 USB 传输仍需在手机保持接收的条件下验证。

## 不依赖 iOS SDK 的开发预览

```sh
cargo run --locked --features mobile --example ios-transfer -- \
  --config-dir ./target/ios-transfer-preview
```

终端会输出临时地址，在本机或同一局域网的电脑浏览器打开即可。可传入
`--duration-seconds 120` 让开发服务在两分钟后自动停止。开发预览使用独立目录，
不会打开播放器窗口或音频设备。

## HTTP 接口约定

接口是初版开发协议，监听临时端口；不使用 Bonjour、路由器端口映射或外部服务器。

| 请求 | 行为 | 认证 |
| --- | --- | --- |
| `GET /` | 返回内嵌的电脑传歌页面 | 静态页面可访问 |
| `GET /api/library` | 返回应用内曲库 JSON | `X-Nano-Token` |
| `POST /api/upload` | 流式接收一个音频并导入 | `X-Nano-Token` |

上传请求：

- 请求体直接为文件字节，不使用 multipart 或 base64。
- `Content-Length` 为必需项，最大 512 MiB；不支持 chunked 传输。
- `X-Nano-Filename` 为经过 URL percent-encoding 的原始文件名。
- `Content-Type: application/octet-stream`。
- 令牌仅通过 `X-Nano-Token` 请求头传递。网页从 URL fragment 读取，fragment
  不会随初次 HTTP 请求发送给服务器。

服务拒绝任意目标目录、路径穿越和不支持的文件类型；重名文件不会覆盖。
上传先写入应用暂存目录，完成后由共享 Storage 校验元数据并发布到曲库。
断传、超时或关闭接收会清理本次临时文件。

服务只处理有限的 HTTP 子集，一次连接一个请求，串行导入。暂不提供断点续传、
双向同步、自动删除、远程播放控制或完整 iTunes 设备管理功能。

## 验证边界

真实 localhost 测试覆盖未认证访问、文件名和长度校验、音频上传、断传清理、
后台到期取消半上传、快速返回前台的竞态、同地址恢复，以及手动关闭撤销会话。
原生后台任务已通过真实 iOS SDK 编译。iPhone 上多设备 Wi-Fi 可达性、系统实际
分配的后台时间、低电量和长时间传输仍需真实场景验证。当前实现采用局域网
HTTP，适合在可信网络内手动开启。
