# Podcast 桌面端实现方案

调研日期：2026-10-19。本文保留原始开发方案；首版已实现，实际范围与验证见[播客实现说明](PODCAST_IMPLEMENTATION.md)。

实现时根据用户追加的原生 UI 要求，核对了手册第 20–21 页：播放页复用歌曲组件，快退改为 30 秒，加入基础速度切换、未听蓝点、时间顺序和自动接续。下文初稿中的「后退 15 秒、播完停止」由这些原生行为取代。

## 建议范围

第一版完成「粘贴 RSS → 订阅节目 → 获取单集列表 → 下载 → 播放 → 断点续听」闭环，沿用现有 iPod 界面和键盘导航，支持 macOS、Windows、Linux 桌面构建。

iOS 和 `--features mobile` 界面继续使用现有占位入口，不接入播客服务、存储或手机同步。首版聚焦音频播客；节目搜索、边下边播、不变调倍速、OPML 导入导出、章节和转录文本作为后续阶段。

## 用户需要提供什么

添加订阅时只需要一个**节目的 RSS 订阅链接**。

| 信息 | 用户是否填写 | 用途 |
| --- | --- | --- |
| RSS URL | 必填 | 获取节目和单集信息 |
| 节目名称、作者、简介、封面 | 自动读取 | 显示节目列表和详情 |
| 单集标题、发布日期、简介、时长 | 自动读取，有些字段可能缺失 | 显示单集列表和播放页 |
| 单集音频地址 | 自动读取 enclosure | 下载音频 |
| 账号、API Key | 公开 RSS 通常不需要 | 第一版直接访问订阅源 |

私人订阅可能用带专属 token 的 RSS URL。必须完整保存其查询参数，显示和诊断日志中隐藏凭证，不把私人链接交给节目搜索服务。需要交互登录的源不在首版范围内。

普通节目网页、Apple Podcasts 分享页、单集网页和 MP3 地址不是 RSS 订阅地址。首版识别到 HTML 时明确提示「请提供节目 RSS 链接」，保留输入供用户修改。节目网页自动发现 RSS、分享链接解析可后续增加。

RSS 的 `<enclosure>` 提供音频 URL、类型和声明大小；`<guid>` 用于单集身份。通用 RSS 允许缺失 GUID，因此客户端仍要有回退策略。[RSS 2.0 规范](https://www.rssboard.org/rss-specification)。Apple 的播客规范另要求稳定 GUID、独立 enclosure，以及托管服务器支持 HEAD 和字节范围请求；这些要求可作为兼容性参考，不能假设所有源都遵守。[Apple 播客 RSS 要求](https://podcasters.apple.com/support/823-podcast-requirements)。

## 桌面交互

保持现有窄屏纵向浏览，不增加复杂的三栏界面：

```text
首页 → Podcasts
  添加订阅…
  继续收听
  最新单集
  已下载
  我的节目列表 → 某个节目 → 单集列表 → 单集详情
                                          播放 / 继续播放
                                          下载 / 取消下载 / 删除下载
                                          标记已听 / 未听
                                          简介
```

- 添加订阅：输入 URL → 后台获取 → 预览封面、名称、作者 → 点击「订阅」。失败保留输入和错误提示；提交前不创建正式订阅。
- 订阅完成只保存元数据，不自动下载历史音频。节目页提供手动刷新和取消订阅。
- 单集列表显示日期、时长、已听状态和下载状态。节目页默认按新到旧排列；播放单集不自动建立音乐队列。
- 未下载单集提供「下载并播放」，明确显示完整下载后才开始。下载期间用户切换播放目标或取消操作，会使原来的自动播放意图失效。
- 播放页显示封面、标题、节目名、进度、音量、暂停、后退 15 秒和前进 30 秒。播放完默认停止，首版不自动播放下一集。
- 复用 J/K、Enter、返回和 Home 行为。文本框聚焦时遵循现有快捷键暂停规则。
- Space、音量、静音、正在播放入口和系统媒体键作用于当前媒体；音乐与播客保留各自的队列/进度。播客界面隐藏音乐评分、歌词、Genius、随机和循环控件。
- 取消订阅后节目从订阅列表隐藏，已下载单集和收听记录保留；删除下载是单独操作。

## 模块和数据

建议新增：

```text
src/podcast/
  mod.rs          FeedId、EpisodeId、领域类型
  feed.rs         RSS → 统一节目/单集模型
  store.rs        SQLite schema、迁移、查询、事务更新
  service.rs      刷新、下载、取消和后台任务事件
  download.rs     流式写盘、完成校验、文件删除
src/app/controller/podcasts.rs
                  桌面服务接线、播放意图、进度持久化
ui/podcasts.slint
                  订阅输入和节目/单集详情
ui/podcast-playing.slint
                  播客播放控件
```

`src/podcast` 使用 `#[cfg(not(any(target_os = "ios", feature = "mobile")))]` 导出。复用 `reqwest::blocking`、`rusqlite` 和现有线程/消息机制，不为首版引入新的异步运行时。RSS 解析优先评估 `rss` crate，首版承诺 RSS 2.0 与常用 iTunes 扩展；用真实样本核对时长、封面、作者和简介字段后锁定版本。其 API 支持从缓冲区读取，解析与网络请求可分离。[rss 文档](https://docs.rs/rss/latest/rss/)。

使用独立的 `<config-dir>/podcasts.sqlite3` 和 `<config-dir>/podcasts/` 目录，不把下载文件导入 `tracks`，不进入音乐统计和 iPhone 同步。

建议五组存储实体：

| 实体 | 关键字段 |
| --- | --- |
| feeds | 本地稳定 ID、订阅 URL、标题、作者、简介、封面 URL、订阅状态、ETag、Last-Modified、最近检查/成功时间 |
| episodes | 本地稳定 ID、feed ID、GUID、音频 URL、MIME、声明字节数、标题、简介、发布日期、时长 |
| episode_progress | episode ID、播放位置毫秒、已听标记、最近播放时间、更新版本 |
| downloads | episode ID、任务版本、状态、本地相对路径、已下载字节数、失败原因 |
| identity_aliases | 原订阅 URL/迁移 URL、单集历史身份与本地 ID 的映射 |

SQLite 连接由存储 worker 独占；网络任务不占用数据库线程。开启外键并使用带版本的 schema 迁移。所有本地文件使用应用生成的 ID 命名，不使用远程标题拼路径。

### 身份和刷新规则

- Feed ID 是数据库生成的稳定 ID。URL 重定向或迁移不改变 ID；保留 URL 别名，避免再次添加时产生重复节目。
- 单集优先按 `(feed_id, guid)` 匹配，GUID 视为不透明字符串。无 GUID 时持久保存基于原 enclosure URL 等信息的回退身份；不能每次刷新重新生成 ID。
- 后续出现 GUID 时，只有能唯一匹配已有 enclosure 等证据才关联旧记录。音频 URL、标题和发布日期可能变动，有歧义时保留记录，不自动合并和转移进度。
- URL 规范化保留路径大小写及查询参数，不删除签名/token，不把不同查询串的私人源视为同一个源。
- 刷新事务只更新远程元数据，不覆盖本地下载、已听标记和播放进度。源不再列出的旧单集仍保留。
- 同一节目的请求带版本，过期刷新结果不能覆盖更新的结果或恢复已取消的订阅。

## 网络与下载

RSS 请求和下载运行在有界后台任务中，初始最多两个并发下载。各任务有独立取消状态；UI 只消费结果和经过节流的进度。退出先停止新任务，再取消网络任务、提交进度写入；不能在 UI 线程无限等待网络结束。

- RSS：设置连接/读取超时、有限重定向、HTTP(S) 协议限制、明确 User-Agent 和响应大小上限。保存缓存验证器，使用条件请求；失败保留上次成功数据。首版由用户手动刷新，后续再增加可配置自动刷新。
- 解析：读取标准 RSS 和 iTunes 元数据，兼容缺失日期/时长；无可播放音频的条目提示不可播放。简介转成适合 Slint 的纯文本，不嵌入网页执行内容。
- 封面：后台下载和解码，有字节及像素上限；缺失/损坏时用占位图，不能阻止订阅或播放。
- 下载：分块写入同目录 `.part`，成功后关闭文件、验证媒体，再发布最终文件并登记完成。HTTP 错误页不能被当作音频缓存。
- RSS 声明大小用于展示和预估，不能当作绝对完整性凭证，动态插入广告可能改变音频；实际传输完整性按 HTTP 响应处理。
- 取消、磁盘写满、断网和校验失败都进入明确状态。首版取消/失败后重新下载；HTTP Range 断点续传属于后续增强。
- 同一单集只允许一个有效下载任务。重新启动时清理或登记未完成 `.part`，并核对数据库中已完成文件是否存在；处理重命名成功但数据库尚未提交的中断窗口。
- 删除当前播放单集的下载时，先停止并保存进度，等音频 worker 确认释放文件后再删除，兼容 Windows 文件占用行为。

## 播放与断点续听

### 复用现有音频引擎

桌面状态增加明确的当前媒体归属，例如 `ActiveMedia::{Music, Podcast, Video}`。播客事件先通过归属与播放句柄检查，再进入播客状态；不能把 EpisodeId 当作 `tracks` 索引。使用现有 generation/epoch 过滤失效事件，后台下载和存储事件另带任务/更新版本。

音乐与播客共享 Rodio Engine。进入播客时取消音乐 gapless 预取并结束音乐统计采样；播客不应用音乐的随机、循环和 ReplayGain 设置。切换视频时复用当前 Stop/Stopped handoff 机制，只有匹配的确认才启动目标媒体，防止同时发声。

当前 Load 无起始位置。建议增加兼容的 `LoadAt` 命令，在 worker 内完成打开文件、seek、建立 sink，再按目标暂停状态输出；原有 Load 保持从零播放。seek 失败返回可展示错误，不能先播放片头再跳转。该变更位于共享音频模块，需要回归原有音乐和移动端调用，但不增加移动端播客功能。

### 进度规则

- 保存媒体时间位置，不按墙上时钟估算。播放时约每 5 秒写一次；暂停、切换媒体、停止和正常退出时补写。
- 更新按顺序或版本提交，较早的自动保存不能覆盖刚执行的「标记已听/未听」或更新的位置。
- 非正常退出最多丢失最近一次保存后的进度，正常重启从保存位置继续。
- 自然播放结束标记已听。拖到末尾不直接视为已听；首版不使用容易误判的「超过 95%」规则。
- 已听单集点击「重新播放」才从零开始；标记未听保留已有位置，并提供独立的「从头播放」。
- 元数据时长可能缺失或不准确。以解码得到的有效时长修正显示和 seek 上限，不因 RSS 时长缩短就清空旧进度。
- macOS 系统媒体信息使用单集标题、节目名、封面和位置。首版系统 Next/Previous 可映射下一/上一集，页内快退/快进保持明确的 15/30 秒；其他系统不声明已支持原生媒体集成。

## 后续能力与取舍

| 能力 | 方案及限制 |
| --- | --- |
| 节目搜索 | 可接 iTunes Search API 的 podcast 查询，拿到 RSS 后仍走统一订阅流程；需实测目标地区可用性、响应字段和请求限制 |
| 边下边播 | 需要支持网络缓冲、Range、跳转、断线恢复和取消的媒体来源；不能把未下载完成文件直接当成普通本地文件 |
| 不变调倍速 | Rodio 0.21.1 的 `Sink::set_speed` 同时改变音调。需要额外时间伸缩处理，或评估抽取现有 libmpv 的纯音频会话 |
| OPML、章节、转录 | 放在核心订阅和收听状态稳定后，分别增加导入导出、章节导航和文本展示 |

Apple 官方文档列出了 podcast 搜索类型和限流要求，但目录发现并不代替 RSS 获取。[iTunes Search API](https://performance-partners.apple.com/search-api)。

倍速的限制见 [Rodio 0.21.1 Sink](https://docs.rs/rodio/0.21.1/rodio/struct.Sink.html#method.set_speed)。mpv 提供速度与音调校正能力，但当前项目封装面向本地视频、创建视频渲染上下文，并非现成的播客播放器；改为纯音频需要验证会话、网络事件、打包和目标机器运行库。首版下载播放不应依赖额外安装 mpv。[mpv 播放选项](https://mpv.io/manual/stable/#options-speed)。

## 开发顺序和验收

1. **存储和 RSS**：实现稳定身份、解析、事务刷新、添加订阅预览。用离线 XML fixtures 和本地 HTTP 服务覆盖缺失 GUID、重复项、URL 变化、重定向、条件请求和坏 XML；刷新失败不能损坏已有缓存。
2. **下载和页面**：接入节目/单集导航、下载状态、取消、删除和重启恢复。验证错误响应、断网、磁盘写入失败、重复下载和中断文件处理；慢网络下键盘与音乐播放保持响应。
3. **播放和续听**：接入 LoadAt、媒体归属、进度保存、播放页和 macOS 媒体信息。验证音乐/播客/视频快速切换、同一单集重开、暂停后退出、旧事件迟到、删除正在播放文件，以及播客不写入音乐统计。
4. **桌面验收**：macOS 做真实订阅、下载、发声、seek 和重启续听；Windows/Linux 分别验证构建、音频和文件生命周期。共享引擎跑现有相关回归，`mobile` 构建确认无桌面播客模块依赖。平台未实测的部分明确记录，不能把可编译等同于可用。

每一步完成后都应可单独验证。第一版完成标准是：订阅一个公开 RSS、浏览并下载一集、从保存位置继续收听，且现有音乐和视频播放保持正常。
